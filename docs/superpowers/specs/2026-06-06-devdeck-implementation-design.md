# DevDeck — дизайн реализации (прототип → приложение)

**Дата:** 2026-06-06
**Статус:** утверждён к планированию
**Источники:** `TZ_DevDeck.md` (ТЗ v1.1), `index.html` (готовый дизайн-прототип фронта)

## Контекст и цель

Есть утверждённое ТЗ на DevDeck — локальный «командный центр» разработчика под
Windows (Tauri 2 + Rust + SQLite) — и готовый визуальный прототип фронта
(`index.html`, ванильный JS, ~2500 строк, моки + метки `// TODO: invoke(...)`).

Цель: превратить прототип в полноценное Tauri-приложение, пройдя весь роадмап
ТЗ (MVP → v1.0 → v2.0).

### Согласованные вводные

- **Фронтенд:** миграция на **Svelte 5 + TypeScript** в режиме **SvelteKit SPA**
  (`adapter-static`, `ssr = false`, `prerender = true`). Изначально планировался плоский
  Svelte+Vite без Kit, но актуальный шаблон `create-tauri-app` (v4.6.2) теперь даёт только
  SvelteKit; пользователь принял Kit-вариант (2026-06-06). SSR не используется — десктоп
  работает как SPA. UI живёт в `src/routes/`, общие модули в `src/lib/` (алиас `$lib`).
- **Охват плана:** весь роадмап MVP → v1.0 → v2.0.
- **Уровень:** новичок в Rust → план с подробными шагами, пояснениями crate'ов и
  типичными граблями.
- **Стратегия:** вертикальные срезы (фича целиком сквозь все слои).
- **Подход к миграции:** вариант A — «скелет, потом срезы»: сначала рабочее окно с
  перенесённой дизайн-системой на моках, затем пофичное «оживление».

## Архитектура

**Стек:** Tauri 2 · Rust-ядро · Svelte 5 + Vite + TypeScript · SQLite через `rusqlite`.

### Структура репозитория

```
devdeck/
├─ src/                      # фронтенд (Svelte)
│  ├─ lib/
│  │  ├─ components/         # Sidebar, Workspace, GitBar, Tabs, Kanban…
│  │  ├─ stores/             # projects, activeProject, theme, ui, toasts
│  │  ├─ api/                # типизированные обёртки над invoke()
│  │  └─ styles/global.css   # вся дизайн-система из прототипа
│  ├─ App.svelte
│  └─ main.ts
├─ src-tauri/
│  ├─ src/
│  │  ├─ main.rs             # точка входа
│  │  ├─ lib.rs              # сборка Tauri, регистрация команд
│  │  ├─ state.rs            # AppState: Mutex<Connection> + ключ шифрования
│  │  ├─ error.rs            # AppError → Serialize (для фронта)
│  │  ├─ db/                 # подключение + раннер миграций
│  │  ├─ models.rs           # структуры (serde) под таблицы
│  │  ├─ commands/           # по модулю на домен: projects, git, creds, tasks…
│  │  └─ crypto.rs           # DPAPI / AES-GCM
│  ├─ migrations/*.sql       # схема из раздела 4 ТЗ
│  └─ tauri.conf.json
├─ CLAUDE.md
└─ package.json
```

### Связь слоёв

- Компоненты **не** зовут `invoke()` напрямую — только через слой `api/` (например
  `projects.list(): Promise<Project[]>`). Единый источник правды по типам и местам
  вызова бэкенда.
- **Долгие операции** (git push/pull, фоновые команды) шлют прогресс через
  **Tauri-события**; `api/` даёт хелпер-подписку, компонент рисует панель/лог.
- **Состояние фронта** — Svelte-сторы: `projects` (грузится из бэкенда),
  `activeProjectId`, `theme`, `ui` (открытые палет/модалки), `toasts`. Подписка
  компонентов заменяет ручные `renderSidebar()`/`renderWorkspace()` прототипа.
- **Состояние Rust** — `tauri::State` с `Mutex<Connection>` (rusqlite синхронный,
  пользователь один → мьютекса достаточно, пул не нужен) + опциональный ключ
  шифрования после разблокировки.

### Обработка ошибок

- Все команды возвращают `Result<T, AppError>`. `AppError` (enum: Db, Git, Io,
  Crypto, NotFound, Validation…) реализует `Serialize` → фронт ловит и показывает
  toast. Никаких `unwrap()` в командах.

### Расположение данных

- `%APPDATA%\DevDeck\devdeck.db` через Tauri path API; папка бэкапов рядом.
- Портативный режим (рядом с `.exe`) — задел, реализуется позже.

### Компоненты фронта (зеркалят render-функции прототипа)

`Sidebar`, `Workspace` (роутер Dashboard ↔ Project), `Dashboard`, `ProjectHeader`,
`GitBar`, `Tabs`, панели `OverviewTab` / `TasksTab` (Kanban) / `ChecklistsTab` /
`CredsTab` / `NotesTab` / `SettingsTab`, плюс `CommandPalette`, `NewProjectModal`,
`Dialog`, `Toasts`.

## Роадмап (вертикальные срезы)

Срез = фича сквозь все слои (миграция БД → Rust-команды → Svelte-компонент на
реальных данных), заканчивается тем, что её видно и можно потыкать руками.

### Phase 0 — Скелет (вариант A)

- `create-tauri-app` (Svelte + Vite + TS), пустое окно запускается.
- **CLAUDE.md** (стек, структура, команды сборки/запуска, конвенции: api-слой,
  `Result<AppError>`, нет `unwrap` в командах, карта модулей).
- Переезд дизайн-системы (CSS) в `global.css`.
- Статический каркас оболочки (Sidebar + Workspace + Dashboard) на моках в сторе.
- Инфраструктура: подключение SQLite + раннер миграций (`PRAGMA user_version`),
  `error.rs`, заготовка `api/`, стор `toasts`, папка бэкапов.
- Итог: красивое окно DevDeck открывается и кликается по моковым данным.

### Phase 1 — MVP

1. **Проекты CRUD** — `projects`/`tags`/`project_tags`; list/get/create/update/
   delete/archive/pin/sort; живые Sidebar, NewProjectModal, ProjectHeader, SettingsTab.
2. **Быстрые действия** — `open_path`/`open_in_editor`/`open_terminal`/`open_url`
   (`std::process::Command`, `explorer.exe`, `wt -d` с фолбэком на cmd/powershell);
   кнопки шапки и «Обзора».
3. **Git** — `git_status` (чтение через `git2`), `git_fetch/pull/push` (системный
   `git` + прогресс событием), `git_commit_all`; GitBar + блок «Требуют внимания».
4. **Креды** — `credentials`, шифрование **DPAPI**, get_secret/create/update/delete,
   CredsTab, копирование с авто-очисткой буфера.
5. **Задачи + Чеклисты** — `tasks`/`checklists`/`checklist_items`; CRUD + DnD с
   сохранением `status`/`sort_order`.
- Итог: собирается `.exe`, ежедневно полезен.

### Phase 2 — v1.0

6. Заметки (Markdown, `marked.js`, автосохранение).
7. Ссылки + файлы-ярлыки.
8. Кастомные команды-кнопки (терминал + фон с захватом stdout и кнопкой «стоп»).
9. Командный палет (Ctrl+K) + глобальный поиск (`search_global`).
10. Дашборд, темы (сохранение), системный трей.
11. Бэкап/экспорт/импорт, шаблоны чеклистов, режим мастер-пароля (AES-GCM + Argon2).

### Phase 3 — v2.0 (если зайдёт)

12. Слежение за папкой (`notify`) — индикатор изменений.
13. Настраиваемые колонки канбана, метки, фильтры.

Порядок внутри Phase 1 намеренный: проекты (фундамент) → быстрые действия (дёшево,
сразу ценно) → git → креды → задачи. Шаблоны чеклистов — в v1.0 (как в ТЗ); в MVP
обычные чеклисты.

## Сквозные вопросы

### Безопасность кредов

- MVP: только **DPAPI** (`CryptProtectData`/`CryptUnprotectData` через `windows`
  crate) — без трения, ключ привязан к учётке Windows.
- v1.0: **режим мастер-пароля** (Argon2id → ключ → AES-256-GCM), выбор при первом
  запуске. В БД только `secret_encrypted` (BLOB) + соль/nonce.
- Секреты не в логах; открытый вид — только по явному «показать»; авто-очистка
  буфера через N секунд (опция).

### Ошибки и обратная связь

- `AppError` сериализуется; единый перехватчик в `api/` → toast ok/info/error.
- Подтверждения перед удалением проекта/кредов.

### Тестирование (прагматично)

- Rust-юниты на легко-ломаемую логику: раннер миграций, шифрование (round-trip),
  парсинг git-статуса, сериализация моделей. БД-тесты на in-memory SQLite.
- Фронт: лёгкий Vitest на сторы и `api`-обёртки; остальное — ручная проверка.
- E2E на старте не делаем.

### Сборка и поставка

- `npm run tauri dev` — разработка; `npm run tauri build` → `.msi`/`.exe`.
- WebView2: предустановлен в Win11; для Win10 — бутстраппер Tauri в `tauri.conf.json`.
- Авто-бэкап БД при старте (последние N копий) — срез 11; папка бэкапов закладывается
  в Phase 0.

## Вне области (YAGNI)

Мультиюзерность, облако/синхронизация, аккаунты, телеметрия, перенос между ПК сверх
режима мастер-пароля, плагинная система. Все «идеи на будущее» (раздел 12 ТЗ) — вне
плана до отдельного запроса.

## Известные расхождения прототипа и ТЗ (учесть при реализации)

- Статусы в моках на русском (`"Активен"`) vs enum схемы `active|paused|done|archived`
  — БД хранит enum, UI отображает локализованную метку.
- Типы кредов в моках текстовые (`"API-ключ"`) vs enum схемы
  `login|api_key|token|ssh|conn_string|note` — аналогично.
- Отдельной вкладки «Ссылки/Файлы» в прототипе нет (ссылки живут в «Обзоре») —
  следуем прототипу; файлы-ярлыки добавляем в срезе 7.
- Глобальный поиск по задачам/заметкам в прототипе пока не реализован (есть только
  фильтр сайдбара) — полноценный `search_global` появляется в срезе 9.
