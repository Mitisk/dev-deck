# Редактор кредов: показ полей по типу

Дата: 2026-07-02
Статус: согласовано, к реализации

## Проблема / цель

Редактор креда ([CredsTab.svelte](../../../src/lib/components/CredsTab.svelte))
показывает все поля независимо от типа. Нужно показывать только релевантные
выбранному типу поля и адаптировать пару подписей.

## Область

**Только фронтенд, один файл** — модалка редактора в `CredsTab.svelte`. Бэкенд,
`CredInput`, save-логика НЕ меняются. Скрытые поля **сохраняют** свои значения
(состояние формы не очищается; при save отправляются как есть — «сохранять скрыто,
не терять»). Карточка креда не меняется (она уже показывает только заполненные
строки).

## Всегда показываются

`Название` (label), `Тип` (select), `Заметка` (notes), тумблер «Показывать во всех
проектах» (для существующего креда). Блок «Секрет» с генератором/индикатором —
вместе с полем секрета (см. матрицу).

## Матрица видимости (по `fType`)

| Поле \ Тип | login | api_key | token | ssh | conn_string | note |
|---|---|---|---|---|---|---|
| Логин/хост (`fUser`) | ✓ | — | — | ✓ | — | — |
| URL (`fUrl`) | ✓ | ✓ | ✓ | ✓ | — | — |
| Путь к ключу (`fKeyPath`) | — | — | — | ✓ | — | — |
| Секрет (`fSecret` + генератор/метр) | ✓ | ✓ | ✓ | ✓ | ✓ | — |

Условия (в разметке):
- `fUser`: `fType === 'login' || fType === 'ssh'`
- `fUrl`: `fType === 'login' || fType === 'api_key' || fType === 'token' || fType === 'ssh'`
- `fKeyPath`: `fType === 'ssh'`
- секрет-блок: `fType !== 'note'`

### SSH — оба режима аутентификации

Для `ssh` показываются ВСЕ четыре поля подключения одновременно: `Логин` (fUser),
`Хост` (fUrl), `Пароль` (fSecret) и селектор `.ppk`-ключа (fKeyPath, кнопка выбора
файла). Пользователь заполняет нужное:
- только ключ → указать `.ppk`, пароль пуст;
- логин/пароль → заполнить пароль, ключ пуст;
- логин/пароль/ключ → заполнить всё.

Бэкенд уже реализует политику «ключ → `-i`, иначе `-pw`» (`build_putty_args`),
поэтому логика запуска PuTTY менять не нужно. Файловый пикер ключа уже фильтрует
`.ppk` первым (`extensions: ["ppk","pem","key"]`).

## Адаптивные подписи (derived от `fType`)

- **Логин/хост** → всегда «Логин» (показывается только у login/ssh, где это логин).
- **URL** → `login`: «Сайт»; `api_key`: «Endpoint»; `token`: «URL»; `ssh`: «Хост».
- **Секрет** → `login`/`ssh`: «Пароль»; `api_key`: «Ключ»; `token`: «Токен»;
  `conn_string`: «Строка подключения». (Плейсхолдер `(пусто = не менять)` при
  редактировании сохраняется.)

Реализовать двумя `$derived`-строками (`urlLabel`, `secretLabel`) — чистые
выражения от `fType`; либо маленькие функции. Подпись «Логин» — статичная.

## Данные / поведение

- Скрытие — через `{#if}` вокруг существующих `.field`-блоков; значения `fState`
  не трогаем. При save `input` формируется как сейчас (все поля), поэтому скрытые
  значения сохраняются.
- Сетка `set-grid` (2 колонки) при скрытии полей просто перетекает — отдельная
  вёрстка не нужна.

## Тестирование

- Автотестов компонента нет (нет инфраструктуры). Проверка `npm run check`
  (0 ошибок) + ручная: переключение типа в редакторе показывает/прячет нужные
  поля; подписи меняются; сохранение не теряет ранее введённые (ныне скрытые)
  значения.
