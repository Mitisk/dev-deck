# ТЗ: DevDeck — менеджер личных проектов под Windows

**Версия:** 1.1
**Тип:** Десктопное приложение (Windows)
**Стек:** Tauri 2 (Rust-ядро + HTML/CSS/JS-интерфейс), SQLite
**Пользователь:** один человек (разработчик), локальная работа без облака

> Рабочее название — DevDeck. Можно поменять на любое.

---

## 1. Общие сведения

### 1.1 Назначение
Персональный «командный центр» разработчика: единое окно, из которого видно все свои проекты и можно мгновенно сделать с проектом всё типовое — открыть папку и редактор, дёрнуть git push/pull, скопировать креды, отметить задачу, запустить `npm run dev` одной кнопкой.

Главная ценность — **минимум кликов** между «вспомнил про проект» и «работаю над ним».

### 1.2 Ключевые принципы
- **Local-first.** Все данные на диске пользователя, без сервера, без аккаунтов, без телеметрии.
- **Один пользователь.** Никакой мультиюзерности, ролей, синхронизации (но с заделом на бэкап/экспорт).
- **Без лишней сложности.** Каждая фича либо экономит клики, либо хранит то, что иначе разбросано по заметкам/закладкам/файлам.
- **Дизайн отдельно от логики.** Интерфейс верстается как обычный веб (HTML/CSS), вся «тяжёлая» работа — в Rust.

## 2. Технологический стек

| Слой | Технология | Комментарий |
|------|-----------|-------------|
| Каркас приложения | **Tauri 2.x** | Окно на системном WebView2, сборка в `.msi`/`.exe`, бинарник ~5–15 МБ |
| Ядро / бэкенд | **Rust** | Бизнес-логика, доступ к БД, git, файловой системе, shell |
| Интерфейс | **HTML + CSS + JS** | Можно «ванильный» JS или лёгкий фреймворк (рекомендация — Svelte: компактный, без рантайма-веса) |
| Хранилище | **SQLite** | Через `rusqlite` (синхронно, просто) или `tauri-plugin-sql` |
| Git | `git2` (libgit2) + системный `git` | См. раздел 5.3 |
| Шифрование кредов | Windows DPAPI / `aes-gcm` + `argon2` | См. раздел 7 |
| Markdown | `marked.js` (фронт) | Рендер заметок |
| Доп. crates | `notify` (слежение за папкой, опц.), `keyring`, `chrono`, `serde` | |

Почему Tauri: нативное окно Windows, веб-вёрстка для красивого UI, Rust для скорости и безопасной работы с файлами/git, крошечный размер по сравнению с Electron.

## 3. Архитектура

```
┌─────────────────────────────────────────────┐
│  WebView2 (фронтенд: HTML / CSS / JS)         │
│  — экраны, формы, канбан, редактор заметок    │
└───────────────┬───────────────────────────────┘
                │  Tauri IPC (invoke / events)
┌───────────────▼───────────────────────────────┐
│  Rust-ядро (Tauri commands)                    │
│  ┌──────────┬──────────┬──────────┬─────────┐ │
│  │ Projects │  Git     │ Creds    │ Shell   │ │
│  │ Tasks    │  Files   │ Crypto   │ Search  │ │
│  └────┬─────┴────┬─────┴────┬─────┴────┬────┘ │
└───────┼──────────┼──────────┼──────────┼───────┘
        │          │          │          │
   ┌────▼───┐ ┌────▼───┐ ┌────▼────┐ ┌───▼────┐
   │ SQLite │ │  Git   │ │ DPAPI/  │ │ explorer│
   │  .db   │ │ (repo) │ │ keyring │ │ code/wt │
   └────────┘ └────────┘ └─────────┘ └─────────┘
```

**Поток:** фронт вызывает Rust-команду через `invoke("имя", {args})` → Rust работает с БД/git/ФС → возвращает результат (или эмитит событие для долгих операций, напр. прогресс git push).

**Расположение данных:**
- По умолчанию: `%APPDATA%\DevDeck\` (БД `devdeck.db`, конфиг, бэкапы).
- Портативный режим (опция): хранить рядом с `.exe` (для флешки/синка через свой облак).

## 4. Модель данных (SQLite)

```sql
-- Проекты
CREATE TABLE projects (
    id           INTEGER PRIMARY KEY,
    name         TEXT NOT NULL,
    description  TEXT,
    status       TEXT DEFAULT 'active',   -- active | paused | done | archived
    color        TEXT,                    -- HEX для акцента карточки
    icon         TEXT,                    -- emoji или имя иконки
    path         TEXT,                    -- корневая папка проекта
    repo_path    TEXT,                    -- путь к git-репо (часто = path)
    pinned       INTEGER DEFAULT 0,
    sort_order   INTEGER DEFAULT 0,
    created_at   TEXT DEFAULT (datetime('now')),
    updated_at   TEXT DEFAULT (datetime('now'))
);

-- Теги
CREATE TABLE tags (
    id    INTEGER PRIMARY KEY,
    name  TEXT NOT NULL UNIQUE,
    color TEXT
);
CREATE TABLE project_tags (
    project_id INTEGER REFERENCES projects(id) ON DELETE CASCADE,
    tag_id     INTEGER REFERENCES tags(id) ON DELETE CASCADE,
    PRIMARY KEY (project_id, tag_id)
);

-- Креды (секрет хранится зашифрованным)
CREATE TABLE credentials (
    id               INTEGER PRIMARY KEY,
    project_id       INTEGER REFERENCES projects(id) ON DELETE CASCADE,
    label            TEXT NOT NULL,           -- "Прод БД", "Stripe API" и т.п.
    type             TEXT NOT NULL,           -- login | api_key | token | ssh | conn_string | note
    username         TEXT,                    -- логин/хост (не секрет)
    url              TEXT,
    secret_encrypted BLOB,                    -- зашифрованный секрет
    notes            TEXT,
    sort_order       INTEGER DEFAULT 0,
    created_at       TEXT DEFAULT (datetime('now')),
    updated_at       TEXT DEFAULT (datetime('now'))
);

-- Задачи (мини-канбан)
CREATE TABLE tasks (
    id           INTEGER PRIMARY KEY,
    project_id   INTEGER REFERENCES projects(id) ON DELETE CASCADE,
    title        TEXT NOT NULL,
    description  TEXT,
    status       TEXT DEFAULT 'todo',     -- todo | doing | done
    priority     INTEGER DEFAULT 0,       -- 0 норм, 1 важно, 2 срочно
    due_date     TEXT,
    sort_order   INTEGER DEFAULT 0,
    created_at   TEXT DEFAULT (datetime('now')),
    completed_at TEXT
);

-- Чеклисты
CREATE TABLE checklists (
    id         INTEGER PRIMARY KEY,
    project_id INTEGER REFERENCES projects(id) ON DELETE CASCADE,
    title      TEXT NOT NULL,
    sort_order INTEGER DEFAULT 0
);
CREATE TABLE checklist_items (
    id           INTEGER PRIMARY KEY,
    checklist_id INTEGER REFERENCES checklists(id) ON DELETE CASCADE,
    text         TEXT NOT NULL,
    is_done      INTEGER DEFAULT 0,
    sort_order   INTEGER DEFAULT 0
);
-- Шаблоны чеклистов (переиспользуемые, не привязаны к проекту)
CREATE TABLE checklist_templates (
    id         INTEGER PRIMARY KEY,
    name       TEXT NOT NULL,
    items_json TEXT NOT NULL            -- JSON-массив строк
);

-- Заметки (Markdown), может быть несколько на проект
CREATE TABLE notes (
    id         INTEGER PRIMARY KEY,
    project_id INTEGER REFERENCES projects(id) ON DELETE CASCADE,
    title      TEXT,
    content_md TEXT,
    updated_at TEXT DEFAULT (datetime('now'))
);

-- Быстрые ссылки/закладки (localhost, репо, дашборды деплоя, доки)
CREATE TABLE links (
    id         INTEGER PRIMARY KEY,
    project_id INTEGER REFERENCES projects(id) ON DELETE CASCADE,
    label      TEXT NOT NULL,
    url        TEXT NOT NULL,
    icon       TEXT,
    sort_order INTEGER DEFAULT 0
);

-- Кастомные команды-кнопки (npm run dev, cargo run, docker compose up)
CREATE TABLE commands (
    id          INTEGER PRIMARY KEY,
    project_id  INTEGER REFERENCES projects(id) ON DELETE CASCADE,
    label       TEXT NOT NULL,
    command     TEXT NOT NULL,           -- shell-команда
    working_dir TEXT,                    -- по умолчанию path проекта
    run_in      TEXT DEFAULT 'terminal', -- terminal | background
    icon        TEXT,
    sort_order  INTEGER DEFAULT 0
);

-- Настройки приложения (ключ-значение)
CREATE TABLE settings (
    key   TEXT PRIMARY KEY,
    value TEXT
);
```

## 5. Функциональные требования

### 5.1 Проекты
- Создание/редактирование/удаление/архивирование проекта.
- Поля: имя, описание, статус, цвет, иконка (emoji), корневая папка, git-папка, теги.
- **Список проектов** в левом сайдбаре: поиск по имени, фильтр по тегам и статусу, закреплённые наверху, перетаскивание для сортировки.
- Карточка проекта = рабочая область со вкладками (см. UI).
- Шапка проекта: имя, цветовая полоса, статус, теги + строка **быстрых действий** (см. 5.4) и **git-сводка** (см. 5.3).

### 5.2 Креды
- Несколько кредов на проект, с типизацией: логин/пароль, API-ключ, токен, SSH-ключ, строка подключения, защищённая заметка.
- Секретное поле хранится **зашифрованным** (раздел 7).
- В интерфейсе секрет по умолчанию замаскирован (`••••••`), кнопки: показать/скрыть, **копировать в один клик** (с авто-очисткой буфера обмена через N секунд — опция).
- Несекретные поля (логин, хост, URL) видны и копируются свободно.
- Поиск по кредам внутри проекта.

### 5.3 Git-интеграция
Гибридный подход (надёжность + переиспользование настроенных кредов системы):
- **Чтение состояния через `git2`** (быстро, без аутентификации): текущая ветка, ahead/behind относительно upstream, число изменённых/застейдженных файлов, последний коммит (хэш + сообщение + дата).
- **Сетевые операции через системный `git`** (`fetch`/`pull`/`push`): чтобы использовать уже настроенные у пользователя SSH-агент / Git Credential Manager и не изобретать хранение git-кредов.
- Кнопки в шапке проекта: **Pull**, **Push**, **Fetch**, **Status**, индикатор «грязного» дерева (точка/счётчик).
- Быстрый коммит: поле сообщения + «Commit all» (`add -A && commit -m`) + опционально сразу push.
- Долгие операции (push/pull) показывают прогресс/лог в всплывающей панели; результат — toast «успешно/ошибка + текст».
- Если у проекта не задан `repo_path` или это не git-репо — git-панель скрыта, предлагается «Init repo» / «указать путь».

### 5.4 Быстрые действия и кастомные команды
Встроенные кнопки (для проекта с заданной папкой):
- **Открыть папку** → `explorer.exe <path>`.
- **Открыть в редакторе** → настраиваемая команда (по умолчанию `code <path>`; можно задать свой редактор в настройках).
- **Открыть терминал здесь** → Windows Terminal `wt -d <path>` с фолбэком на `cmd`/`powershell`.
- **Открыть в браузере** → для каждой ссылки из раздела 5.8.

Кастомные команды (таблица `commands`) — это **«фишка»**:
- Пользователь добавляет свои кнопки: ярлык + shell-команда + рабочая папка.
- Примеры: `npm run dev`, `cargo run`, `docker compose up -d`, `php yii serve`.
- Режим запуска: **в терминале** (открыть окно, видно вывод) или **в фоне** (с захватом stdout в панель логов внутри приложения, с кнопкой «остановить»).
- Иконка/цвет кнопки на выбор.

### 5.5 Задачи (мини-канбан)
- Три колонки: **To Do / In Progress / Done** (названия фиксированы в MVP).
- Карточка задачи: заголовок, описание (опц.), приоритет (цветовая метка), срок.
- Drag-and-drop между колонками и внутри колонки (меняет `status` и `sort_order`).
- Быстрое добавление: поле «+ задача» в каждой колонке.
- Выполненные можно сворачивать/скрывать.

### 5.6 Чеклисты
- Несколько чеклистов на проект, каждый — список пунктов с галочками и прогресс-баром (X из Y).
- Добавление/редактирование/удаление/перетаскивание пунктов.
- **Шаблоны чеклистов**: сохранить текущий чеклист как шаблон и применять к любому проекту (напр. «Чеклист релиза», «Деплой», «Старт нового проекта»).

### 5.7 Заметки
- Несколько Markdown-заметок на проект.
- Редактор с разделением «исходник / превью» или переключателем; рендер через `marked.js`.
- Автосохранение при потере фокуса/периодически.

### 5.8 Ссылки и файлы
- **Ссылки**: именованные закладки проекта (localhost:3000, репозиторий на GitHub, дашборд деплоя, документация). Открываются в браузере одной кнопкой.
- **Файлы/папки**: список путей-ярлыков (файл `.env`, папка `docs`, конфиг) — открыть файл ассоциированной программой или показать в проводнике.

### 5.9 Глобальный поиск и командный палет
- **Командный палет (Ctrl+K)** — «фишка» для разработчика: быстрый переход к проекту, запуск действия (открыть папку проекта X, push проекта Y, скопировать кред Z) без мыши.
- **Глобальный поиск** по проектам, задачам, заметкам, ссылкам.

### 5.10 Дашборд (стартовый экран)
- Закреплённые проекты (большие карточки с быстрыми действиями).
- Недавно открытые проекты.
- Задачи со сроком сегодня/просроченные (по всем проектам).

### 5.11 Системный трей
- Иконка в трее: свернуть в трей вместо закрытия (опция).
- Меню трея: 3–5 закреплённых проектов, «открыть приложение».

## 7. Безопасность кредов

Два режима на выбор (настройка при первом запуске):

1. **DPAPI (по умолчанию, без трения).** Шифрование секретов через Windows Data Protection API — ключ привязан к учётной записи Windows. Не нужен мастер-пароль, но данные расшифровываются только на этой машине/под этим пользователем. Подходит для портативности «в рамках одного ПК».

2. **Мастер-пароль (для максимальной защиты / переноса между ПК).** При запуске спрашивается мастер-пароль → из него `Argon2id` выводит ключ → секреты шифруются `AES-256-GCM`. БД можно безопасно носить с собой; без пароля креды не открыть.

Общие правила:
- В БД хранится только зашифрованный `secret_encrypted` (BLOB) + соль/nonce.
- Секреты не пишутся в логи и не выводятся в открытом виде без явного «показать».
- Опция автоочистки буфера обмена через N секунд после копирования секрета.

## 8. Хранение, бэкап, портативность
- Все данные — один файл `devdeck.db` (SQLite) + папка бэкапов.
- **Авто-бэкап**: копия БД при старте/раз в день, хранить последние N копий.
- **Экспорт/импорт**: выгрузка в JSON (без расшифровки секретов или с расшифровкой по подтверждению) для переноса/архивации.
- Портативный режим: всё рядом с `.exe`.

---

## 9. Нефункциональные требования
- **Производительность:** холодный старт < 1 с; список из сотен проектов без лагов.
- **Размер:** инсталлятор/бинарник в пределах ~15 МБ.
- **Офлайн:** полная работа без интернета (кроме git push/pull и открытия ссылок).
- **Без телеметрии**, без обязательных аккаунтов.
- **ОС:** Windows 10/11 x64 (WebView2 предустановлен в Win11; для Win10 — бутстраппер Tauri).

## 10. IPC API (Rust-команды, верхнеуровнево)

| Команда | Назначение |
|---------|-----------|
| `projects_list / get / create / update / delete / archive` | CRUD проектов |
| `project_set_pinned / set_sort` | Закрепление и сортировка |
| `creds_list / get_secret / create / update / delete` | Креды (расшифровка по запросу) |
| `git_status(repo_path)` | Ветка, ahead/behind, dirty-файлы, последний коммит |
| `git_fetch / git_pull / git_push(repo_path)` | Сетевые операции (стрим прогресса событием) |
| `git_commit_all(repo_path, message)` | Быстрый коммит |
| `open_path / open_in_editor / open_terminal / open_url` | Быстрые действия |
| `command_run(command_id)` / `command_stop(run_id)` | Кастомные команды (фон/терминал) |
| `tasks_list / create / update / move / delete` | Канбан |
| `checklists_* / checklist_items_* / templates_*` | Чеклисты и шаблоны |
| `notes_* / links_* / commands_*` | CRUD соответствующих сущностей |
| `search_global(query)` | Глобальный поиск |
| `backup_now / export_json / import_json` | Бэкап и экспорт |
